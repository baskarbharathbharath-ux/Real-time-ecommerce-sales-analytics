# Real-Time E-Commerce Sales Analytics — Project Report

## 1. Project Overview
This project demonstrates a simulated real-time analytics pipeline for an e-commerce business. A Python script generates order events at regular intervals and inserts them into Oracle Database. SQL queries and views prepare the data for reporting, and Power BI visualizes sales performance.

## 2. Business Problem
E-commerce teams need timely visibility into order volume, revenue, product demand, payment preferences, geographic performance, and cancelled orders. Periodic manual reporting can delay decisions.

## 3. Objectives
- Simulate a continuous stream of e-commerce orders.
- Store structured order data in Oracle Database.
- Use SQL to calculate sales KPIs and rank products/categories.
- Build a Power BI dashboard for monitoring business performance.
- Demonstrate an end-to-end analytics workflow suitable for a portfolio.

## 4. Dataset Description
The dataset is synthetic and is generated by `python/simulate_sales.py`.

| Field | Description |
|---|---|
| ORDER_ID | Unique order identifier |
| ORDER_TIMESTAMP | Time the simulated order was created |
| CUSTOMER_ID | Synthetic customer identifier |
| PRODUCT_ID / PRODUCT_NAME | Product identifiers and names |
| CATEGORY | Product category |
| QUANTITY | Number of units in the order |
| UNIT_PRICE | Price per unit in INR |
| DISCOUNT_PCT | Discount fraction, from 0 to 1 |
| NET_AMOUNT | Amount after discount |
| PAYMENT_METHOD | Simulated payment type |
| CITY | Simulated customer city |
| ORDER_STATUS | COMPLETED, PROCESSING, or CANCELLED |

## 5. Tools and Technologies
- Python: data generation and database insertion
- Oracle Database: storage and SQL analysis
- Oracle SQL Developer: execute SQL scripts and inspect data
- Power BI Desktop: KPI cards, charts, slicers, and dashboard
- GitHub: version control and project presentation

## 6. Methodology
1. Create the Oracle table and indexes.
2. Configure Python environment and Oracle credentials.
3. Test the database connection.
4. Run the simulator to insert orders at regular intervals.
5. Create SQL views and execute analysis queries.
6. Connect Power BI to Oracle and build dashboard visuals.
7. Refresh the report and validate that newly generated orders appear.

## 7. Dashboard Design
KPI cards: Total Revenue, Total Orders, Units Sold, Average Order Value, Cancellation Rate, and Latest Order Time.

Visuals:
- Revenue over time
- Revenue by product
- Revenue by category
- Orders by payment method
- Revenue by city
- Latest orders table

Filters: date, category, city, payment method, and order status.

## 9. Business Recommendations
- Prioritize replenishment for products with high unit sales and low inventory (inventory data would need to be added to validate stock risk).
- Review product/category performance and test promotions for lower-performing categories.
- Track cancellation rate over time and investigate any increase.
- Compare payment methods and cities to identify operational or marketing opportunities.
- Monitor average order value and evaluate bundles or threshold-based offers.

## 10. Limitations
- All orders and customers are synthetic; they do not represent a real retailer.
- The simulator creates one order per interval and is not a production message broker.
- Dashboard freshness depends on Power BI connection mode and refresh configuration.
- The dataset does not contain product costs, inventory, shipping events, or customer demographics, so profit and delivery performance cannot be calculated.

## 11. Conclusion
The project demonstrates a practical analytics workflow connecting Python, Oracle SQL, and Power BI. It provides a foundation for more advanced work such as API ingestion, streaming platforms, inventory tracking, and profit analysis.
